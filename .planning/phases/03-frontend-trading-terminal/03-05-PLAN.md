## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input → REST mutation | unvalidated form input crosses into POST/DELETE endpoints (backend is authoritative) |
| LLM content → chat DOM | untrusted assistant message/error text renders into the page (prompt injection surface) |
| backend response → client state | mutation responses and the 503 chat body cross into the store |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | ChatPanel message/error rendering | high | mitigate | LLM content renders as TEXT via React auto-escaping — never raw-HTML injection (ASVS V5, 03-RESEARCH.md:534); confirmations render from structured trades/watchlist_changes fields only; the XSS behavior test asserts zero parsed elements from a tag-shaped message (ChatPanel.test.tsx behavior 4). |
| T-03-08 | Tampering | TradeBar/WatchlistPanel input | medium | mitigate | Client pre-validation is UX-only (ticker ≤ 12 chars via /^[A-Z0-9.]{1,12}$/, quantity > 0); the backend Pydantic schemas stay authoritative and reject forged bodies with 422/400/404/409 (03-RESEARCH.md:249, 527). |
| T-03-04 | Tampering | store state after mutations | low | accept | All mutations execute server-side; the client reconciles from the response. A forged local state changes only the cosmetic view (03-RESEARCH.md:537). |
</threat_model>
