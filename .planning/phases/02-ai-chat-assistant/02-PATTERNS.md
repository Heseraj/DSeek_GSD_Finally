### `backend/app/chat/schemas.py` (model, transform)

**Analog:** `backend/app/portfolio/schemas.py` (42 lines)

**Imports pattern** (lines 1-7):
```python
"""Pydantic request/response schemas for the portfolio API."""

from __future__ import annotations

from typing import Literal

from pydantic import BaseModel, Field, field_validator
```

**Request-model + validator pattern** (lines 10-21) — copy the `field_validator` ticker-normalization pattern so LLM-proposed tickers like `" aapl "` normalize the same way as manual trades (RESEARCH anti-pattern: "do not invent a second validation path"):
```python
class TradeRequest(BaseModel):
    """A market order to buy or sell shares at the current price."""

    ticker: str
    quantity: float = Field(gt=0, description="Number of shares; fractional shares supported")
    side: Literal["buy", "sell"]

    @field_validator("ticker")
    @classmethod
    def normalize_ticker(cls, value: str) -> str:
        """Uppercase and strip whitespace so ' aapl ' trades as 'AAPL'."""
        return value.strip().upper()
```

**Nested response-model pattern** (lines 36-42) — `ChatResponse` should nest `TradeAction`/`WatchlistChange` result models exactly like `PortfolioResponse` nests `PositionResponse`:
```python
class PortfolioResponse(BaseModel):
    """The portfolio shape: cash, positions, total value, and unrealized P&L."""

    cash_balance: float
    positions: list[PositionResponse]
    total_value: float
    unrealized_pnl: float
```

**Notes for the planner:**
- `ChatRequest` = `{message: str}` (user input, Pydantic-validated per ASVS V5).
- `ChatResponse` must mirror the RESEARCH §9 envelope: `{message, trades: [TradeActionResult...], watchlist_changes: [WatchlistChangeResult...], error?: str}` — each result carries `status: "executed"|"failed"` and optional `error`, so the 503 no-key body (`{"message": "...", "trades": [], "watchlist_changes": [], "error": "..."}`) is a *valid* `ChatResponse` instance (RESEARCH Open Question 3).
- Parse LLM output with `ChatResponse.model_validate_json(content)` (tolerant fallback on `ValidationError` per RESEARCH Pitfall 2) — do NOT reuse `TradeRequest` as the wire schema; construct `TradeRequest(**proposal)` inside the executor instead.

```python

... str(uuid.uuid4()) ...
```

**Key design points for the planner (from RESEARCH):**
1. **Provider seam at call time** (CHAT-05): `generate_assistant_response(...)` reads `os.environ.get("LLM_MOCK")` *inside* the call; mock returns a canned dict (RESEARCH line 268-275), live path awaits `litellm.acompletion(...)` (RESEARCH lines 245-262). Both return the same shape; the caller (parse + execute) is identical. Never read env at import time (un-patchable).
2. **Per-action error capture** (Pattern 2, RESEARCH lines 158-173): `_execute_trade(conn, price_cache, proposal)` wraps `TradeRequest(**proposal)` + `execute_trade` in try/except `TradeError`, returns `{**proposal, "status": "executed"}` or `{**proposal, "status": "failed", "error": str(exc)}`. Watchlist equivalents map `(ticker, created)` → executed/conflict and `removed: bool` → executed/404. Never re-raise from the executor.
3. **History load + save** (Pattern 3, RESEARCH lines 277-285): `SELECT role, content, actions FROM chat_messages WHERE user_id = 'default' ORDER BY created_at DESC LIMIT 20` reversed; after execution INSERT user row (actions NULL) + assistant row (actions = JSON) in one `with conn:` block.
4. **Error mapping for live LLM**: catch `litellm.exceptions.AuthenticationError` / `APIConnectionError` / `Timeout` (all `APIError` subclasses) → return a valid `ChatResponse` shape with `error` set (RESEARCH Pitfall 5 / Open Question 3).

**Async handler with `app.state` DI + conn lifecycle** (watchlist/router.py lines 32-51):
```python
@router.post("")
async def add_watchlist_ticker(request: Request, payload: WatchlistAddRequest) -> dict:
    db_path: str = request.app.state.db_path
    market_source: MarketDataSource = request.app.state.market_source

    conn = get_connection(db_path)
    try:
        ticker, created = await add_ticker(conn, market_source, payload.ticker)
    finally:
        conn.close()

    if not created:
        raise HTTPException(status_code=409, detail=f"Ticker already on watchlist: {ticker}")
    return {"ticker": ticker}
```

**Chat handler shape:** `async def chat(request: Request, payload: ChatRequest) -> ChatResponse` reading `request.app.state.db_path`, `request.app.state.price_cache`, `request.app.state.market_source`, then `conn = get_connection(db_path)` / `try: return await process_message(...)` / `finally: conn.close()`. The handler is `async def` because `process_message` awaits `add_ticker`/`remove_ticker` (RESEARCH Pitfall 4: forgetting `await` on these is the #1 watchlist bug). No `HTTPException` for LLM-unavailable — return the 503-shaped `ChatResponse` with `error` field set (RESEARCH Open Question 3; frontend renders it without special-casing). Use `@router.post("")` — the existing routers use `""` not `"/"`.

class MockMarketSource:

        self.tracked: set[str] = set()
        self.cache = PriceCache()

    async def add_ticker(self, ticker: str) -> None:
        self.tracked.add(ticker)
        self.cache.update(ticker=ticker, price=100.0)

    async def remove_ticker(self, ticker: str) -> None:
        self.tracked.discard(ticker)
        self.cache.remove(ticker)

    def get_tickers(self) -> list[str]:
        return sorted(self.tracked)
